# 开发约定

> 本文面向本仓库的开发协作（含 AI Coding Agent），不是对外产品说明。

# 项目定位

本项目主要用于开发 Windows 11 桌面工具，包括效率工具、AI 工具、开发者工具、文件处理工具和自动化工具。

目标不是做 Demo，而是尽量形成真正可运行、可测试、可发布、可持续维护的 Windows 产品。

# 默认开发原则

- 优先个人开发者可维护性，避免企业级过度设计。
- 技术方案优先成熟、简单、低成本、易调试、易打包、易发布。
- 开发优先级：**可运行 > 可用 > 稳定 > 体验 > 架构优雅**。
- 先完成完整可用闭环，再逐步优化架构和体验。
- 修改已有项目时，先理解现有代码和设计，不轻易重构。
- 除非现有架构明显阻碍目标，否则优先最小必要修改。
- 不为了“最佳实践”引入不必要的框架、抽象层或依赖。

# Windows 平台要求

默认目标平台为 Windows 11，并重点考虑：

- 文件系统与本地文件处理
- 剪贴板
- 文件拖拽
- 全局快捷键
- 系统托盘
- Windows 通知
- 开机启动
- 单实例运行
- 权限与 UAC
- 高 DPI / 多显示器
- 深色模式
- 安装、卸载与升级
- 自动更新
- 崩溃恢复与日志
- 配置持久化
- Windows 原生交互习惯

涉及这些能力时，应优先采用稳定、成熟的 Windows 实现方式。

# UI / UX

UI 默认追求：

- Windows 11 风格
- 现代、简洁
- 信息密度适中
- 操作路径短
- 状态反馈明确
- 避免传统工具软件的老旧视觉
- 避免为了视觉效果牺牲可用性

优先保证实际使用效率，而不是单纯追求动画和装饰效果。

# AI Coding Agent 协作方式

项目主要通过 Codex、Claude Code、Grok Build 等 AI Coding Agent 辅助开发。

因此需求、Plan 和任务应尽量：

- 明确
- 可执行
- 可验证
- 可逐步提交
- 避免模糊描述

复杂任务优先使用：

**Goal → Current State → Tasks → Constraints → Acceptance Criteria**

开发过程中应主动推进能够确定的工作，不因低价值细节频繁中断询问。

# 代码修改原则

处理已有代码时：

1. 先阅读和理解现有实现。
2. 找出问题根因，而不是只修表面现象。
3. 优先局部修改。
4. 保持现有项目风格。
5. 避免无关重构。
6. 修改后检查相关功能是否产生回归。
7. 必要时补充日志、异常处理和边界条件。
8. 不留下明显 TODO、占位实现或假数据冒充完成状态。

# 技术选型原则

没有明确技术栈时，根据产品需求选择方案，不固定框架。

选择顺序重点考虑：

1. Windows 能力支持程度
2. 开发效率
3. AI Agent 修改代码的可靠性
4. 打包与发布难度
5. 性能和资源占用
6. UI 表现
7. 长期维护成本

可根据项目实际需求选择 WinUI 3、WPF、.NET、Tauri、Electron、Qt、Python 等方案，但不要因为流行而默认采用某种技术。

# 完成标准

一个功能不能只以“代码写完”作为完成。

默认至少应满足：

- 能运行
- 核心流程可用
- 异常路径可处理
- 没有明显阻断 Bug
- UI 状态与实际状态一致
- 关键操作有反馈
- 基本边界情况得到处理
- 不破坏已有功能

准备发布时进一步检查：

- 安装 / 卸载
- 首次启动
- 配置保存
- 升级
- 权限
- 路径兼容
- 中文路径
- 高 DPI
- 多显示器
- 崩溃日志
- Windows Defender / SmartScreen 相关影响

# 输出偏好

默认使用简体中文沟通。

技术方案优先给出结论和推荐方案，再说明原因。

除非确有必要，不展开过多理论背景。

对于开发任务，优先输出 Agent 可以直接执行的任务描述、Plan、Goal、检查清单或验收标准。
